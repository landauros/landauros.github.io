图灵机纸带：把计算过程拉成一条可以亲眼看见的带子

通过一条可编辑纸带，交互式理解图灵机怎样读、写、移动，并在有限状态中完成计算。

为什么要做成“纸带”#

很多人第一次接触图灵机时，会觉得它只是一个历史概念：纸带、状态、读写头，像是计算理论课里的古老装置。
但如果你真的把它动起来，就会发现它非常现代。

图灵机最迷人的地方，在于它几乎什么都没有：

  • 一条可以无限延伸的纸带
  • 一个当前位置
  • 一个有限状态
  • 一张转移表

然后，仅靠这些，你就可以定义“计算”。

这也是我想把它做成可交互 demo 的原因。
与其把转移函数写成几行抽象符号，不如让你直接看到：

  1. 当前状态是什么
  2. 机器正在读哪一个格子
  3. 它把什么写回去
  4. 它接下来往左还是往右走
  5. 这一切怎样一步一步累积成结果

这个 demo 里有什么#

当前版本内置了三台小机器：

  1. Unary Increment
    输入一串 1，机器扫到最右端后再补一个 1。

  2. Binary Increment
    输入一个二进制数，比如 1011，机器完成加一运算，把它变成 1100。

  3. Busy Beaver (2-state)
    从空白纸带开始，观察一个极小状态机如何写出比你直觉中更“丰富”的行为。

你可以做的事包括：

  • 改初始纸带
  • 切换不同机器
  • 单步执行
  • 自动运行
  • 对照右侧转移表看当前规则
  • 阅读执行日志

它真正想讲的，不只是图灵机#

这个 demo 表面上在讲“自动机如何读写纸带”，更深一层其实在讲：

计算不是神秘的。它往往只是状态、规则、记忆介质，以及重复执行。

纸带只是最朴素的记忆介质。
状态表只是最朴素的控制逻辑。
但当它们被放在一起时，就已经足够表达非常多的东西。

这也是为什么图灵机直到今天仍然有魅力。
它不是因为“老”，而是因为它把计算的骨架暴露得足够彻底。

怎么玩比较有意思#

如果你想顺着一个比较有教学感的节奏体验，可以这样试：

  1. 先选 Unary Increment，输入 111
  2. 连点几次 Step，观察机器只是不断向右扫描
  3. 注意它直到读到空白格才真正改写纸带
  4. 再切到 Binary Increment，输入 111
  5. 看它如何把尾部的 1 一路变成 0，再向左传播“进位”
  6. 最后切到 Busy Beaver，从空白纸带开始看它为什么会比看起来复杂得多

如果这几个例子你都看顺了，图灵机就不会再只是课本上的定义，而会变成一种你真的“摸过”的计算模型。

小结#

如果只用一句话概括这个 demo，我会说：

它不是在模拟一台古老机器，而是在把“规则如何变成计算”这件事变得可见。

前一篇 MAINFRAME-1960 demo 更像是在讲共享计算与时代轮回。
这一篇则更接近计算理论本身：从一条纸带开始，重新看到程序的最小骨架。
